bidi-kit

Same text, same size, same typeface, same paragraph direction on both sides. The only difference is which characters bidi-kit placed where.

A paragraph is not one direction

dir="rtl" sets the direction of a block. Everything inside it is then ordered per character by the Unicode bidi algorithm, which is correct in isolation and surprising in bulk, because punctuation and digits are neutral: they take their direction from their neighbours.

Boundary

The full stop moves

In an English sentence, the period after an Arabic name is neutral, so it is absorbed into the Arabic run and renders on the wrong side of the name. Nobody wrote it that way; the algorithm cannot know where you meant the boundary.

Numerals

The phone number breaks

Digits have no direction of their own. Inside Arabic, +216 71 123 456 gets sliced into pieces that reassemble in the wrong order — and the + and % that belong to the number travel somewhere else entirely.

Type

The word changes face

If the Latin font has no Arabic glyphs, the browser falls back per glyph and one word is drawn in two faces. A naskh face at a Latin line-height clips the kasra below the baseline.

Two projects, one idea

Direction is decided once, structurally, and then never guessed again. ui-storm does that for the page; bidi-kit does it for the sentence.

Rust · server-rendered

ui-storm

A component library where direction is resolved from the locale, not from a class name: a BCP-47 tag becomes a Direction, the layout writes it to <html dir>, and the stylesheet uses logical properties only.

  • Maud components with props structs and a pure render()
  • Actix Web gallery serving the components and their documentation
  • Contrast maths asserted against the shipped stylesheet
  • Playwright and axe across two themes, two directions, keyboard and no-JavaScript
  • A generated backlog of 907 issues across 15 milestones
TypeScript · npm + CDN

bidi-kit

The inline half. It answers four questions for any string: where does each run start and end, which way does it go, how is it isolated, and which face has the glyphs.

  • segments() — run boundaries, with UTF-16 offsets
  • paragraph(), bdi(), isolate() — isolation, never the deprecated embeddings
  • Arabic font stacks, joining features and @font-face rules
  • audit() and stripBidiControls() — invisible characters as a security problem
  • CLI: bidi-kit check, runs, isolate, dir

Use it from a static page, with one tag

No npm, no bundler, no build step, no module loader. The file is served from the repository through a CDN, so a browser caches it exactly like any other JavaScript file, and a plain .html opened from disk loads it too. 

<script src="https://cdn.jsdelivr.net/gh/Nour-yahyaoui/ui-storm@main/static/bidi-kit.js"></script>
<script>
  const kit = window.bidiKit; // 31 exports, no globals beyond this one
  document.querySelector("#line").innerHTML = kit.paragraph([
    "Sent to ",
    { text: "أحمد بن علي", dir: "rtl", lang: "ar" },
    " this morning.",
  ]);
</script>
// the same package, as a module, straight from npm or the CDN
import { paragraph, CSS } from "bidi-kit";
// or, with no install at all:
import { paragraph } from "https://cdn.jsdelivr.net/npm/bidi-kit@__VERSION__/dist/esm/index.js";
  • Why not raw.githubusercontent.com? It answers with text/plain and nosniff, so browsers refuse to execute it as a script. A CDN in front of the same repository sends a JavaScript content type, which is the whole difference.
  • Cached like any script. The CDN keeps one copy in memory and browsers cache it; pin @main to a tag or a commit when you want a version that never changes.
  • The repository is the source of truth. static/bidi-kit.js is generated from the package build, and CI fails when the committed copy and a fresh build disagree.
  • It ships its own CSS. kit.CSS is a string: inject it once and the isolation, alignment and Arabic line-height rules are in place.

How it is decided

Rules, in one place

  • A strong character starts a run and decides its direction.
  • Arabic punctuation and Arabic-Indic digits stay inside an Arabic run.
  • Latin digits read left to right even inside Arabic, and keep their . , + - %.
  • Brackets, quotes and symbols are neutral: they take their direction from agreeing neighbours, otherwise the base direction.
  • Combining marks and invisible controls never split a word.
  • Isolation uses <bdi> and U+2066–U+2069, never RLE / PDF.
