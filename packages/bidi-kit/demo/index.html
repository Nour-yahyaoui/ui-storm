bidi-kit

Arabic words inside English sentences, French sentences inside Arabic paragraphs — with the punctuation, numbers and fonts that go with them. No dependencies, no fonts bundled, no framework.

zero dependencies ESM + CJS + types browser safe MIT

1 · An Arabic word at the end of an English sentence

The full stop is neutral: the browser keeps it with the Arabic run, so it renders on the wrong side of the word and the sentence looks like it starts with a dot. paragraph() decides the run boundaries, isolates the Arabic run, and leaves the stop in the English sentence.

2 · A French quotation inside an Arabic paragraph

In a right-to-left paragraph the guillemets, the trailing full stop and the Latin words all compete for a direction. Isolating the quotation keeps it readable as French while the paragraph around it stays Arabic.

3 · Numbers, a phone number and an email in Arabic

Digits inside Arabic run left to right; a + or a % that belongs to a number has to travel with it. Left alone, the number's parts get reordered around the neighbouring Arabic words.

4 · A French paragraph with an Arabic name

This is the quieter failure: nothing looks scrambled, but the name is rendered in whatever face the operating system fell back to, the quotes jump sides, and the comma after the name is not the French one. A face with Arabic glyphs and an isolated run fix all three.

5 · Diacritics, and the face that has room for them

A naskh text face at a Latin line-height clips the marks. Both panes use the same string; only the right one is in a font stack chosen for Arabic, at a line-height that leaves the kasra below the baseline somewhere to live.
